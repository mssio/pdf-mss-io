# 1.1.0 plan: real progress bar

Not part of any release gate yet. When 1.1.0 starts, copy its owner checks into `docs/todo.md`.

**Status (2026-10-08):** the package side is in progress in `mssio/qpdf-wasm`, branch
`feat/streaming-progress`. Its spec (`docs/superpowers/specs/2026-10-08-streaming-progress-design.md`) and
plan (`docs/superpowers/plans/2026-10-08-streaming-progress.md`) are written. That release is
`@mssio/qpdf-wasm` 1.1.0. Spec §7 is the guidance for this repo.

## Package side (owner, in the `qpdf-wasm` repo)

The original prompt given to Claude in the `@mssio/qpdf-wasm` repo:

> In `@mssio/qpdf-wasm`, add streaming progress. Give every helper's options and `run()`'s options an
> optional `onProgress?: (percent: number) => void`. When it's set, run qpdf with `--progress`, parse
> each stdout line matching `/write progress: (\d+)%/` as Emscripten prints it (don't wait for the job
> to end), and post `{ type: "progress", id, percent }` from the worker to the main thread. The
> pool/executor forwards these to that job's callback; inline (Node) mode calls it directly. Keep
> progress lines out of `RunResult.stdout`, don't call the callback after the job settles or after
> `terminate()`, and keep the API backward compatible. Add unit and browser tests (percent values
> rise from 0 to 100 for a large encrypt) and README docs, and release it as **1.1.0**.

## This repo

Upgrade to `@mssio/qpdf-wasm@^1.1.0`, pass `onProgress` from `useQpdfJob`, show a percentage bar in
`JobStatus`, and use "no progress for N seconds" for the stuck-engine time limit.
